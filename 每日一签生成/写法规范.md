# 每日一签 · 批次生成写法规范（子代理必读）

## 你的任务

输入 `batches/in_XX.json`（每章含 id/text/source/translation/scene/insight/practice_old）。
为每章输出三个新字段，写入 `batches/out_XX.json`，格式：

```json
[
  {
    "id": 1,
    "clue_m": "……",
    "clue_s": "……",
    "practice": "……"
  }
]
```

- `clue_m` = 中线索（默认显示的"今日线索"）
- `clue_s` = 强线索（更具体的场景钩子）
- `practice` = 今日一试（今天就能做的轻行动，单条字符串）
- 输出数组顺序必须与输入一致，**每章都必须有，一条不能少**
- 只输出 JSON，不要包裹 markdown 代码块，不要加任何解释文字

## 写法基准（风格、口吻、长度以原型 6 句为准）

原型 6 句示例（学而时习之）：
- clue_m：`你最近有没有一样东西——学过的、读过的、收藏过的——其实一直没真正'用'起来？`
- clue_s：`收藏夹、书架、'下次再看'的清单……哪个是你学了却从没让它进过生活的？`
- practice：`今天把你最近学的一个东西，真用上一次——讲给人听、写下来、或用到手头一件事。`

再如（譬如为山）：
- clue_m：`你最近有没有一件'差一点就成了'、却停在那里的事？`
- clue_s：`那件事停的时候，是谁做的决定？是'做不到'，还是'自己签了停'？`
- practice：`今天挑一件停在90%的事，只往前推'一筐土'——不必做完，但要动。`

## 硬规则（逐条自检后再输出）

1. **线索不复述白话**：白话已给句意。线索必须引向"你哪里跟它有关"——用户的生活、处境、情绪。判断法：把 translation 删掉，线索单独看仍然成立、仍然引人联想，才算合格。直接把 translation/insight 换个说法当线索 = 不合格。
2. **clue_m 是"中等强度"**：一个开放的追问，问用户"最近有没有"某种经历/感受，宽口、不预设答案。通常 1 句话，20–45 字，以"？"收尾居多（陈述式钩子也可，但要有"你"）。
3. **clue_s 比 clue_m 更具体**：把范围收窄到一个具体可辨认的时刻/选择/对象，帮卡住的用户进一步对号入座。可 1–2 句，30–60 字。
4. **clue_s 不是 clue_m 的换说法**：两者递进——m 宽、s 窄；m 问有没有、s 帮你定位到哪件事。
5. **practice = 今天就做的轻行动**：一句话，通常以"今天……"开头，15–40 字。**禁止**"本周/这周/接下来一个月/三个月/长期"等周期表述。要具体可做（写下来、发一条消息、推掉一个局、删掉一个收藏……），不做不到的大事。
6. **现代人口吻**：面向有社会阅历的成年人（职场/家庭/关系/自我成长），不用"您"，不用 emoji，不喊口号，不出现"《论语》告诉我们"这类论文腔。
7. **覆盖整章主旨**：有些章很长（多句），抓该章最核心、最有生活钩子的那一句/那层意思来写线索（通常 insight 已经抓对了，跟着它的重心走）。
8. **引文原样**：不要改写原文 text，不要翻译成英文。
9. **不重复用词**：同一章内三段不重复同一关键词组；相邻花样尽量避免"有没有……？"句式在 m/s 间连续两次完全同构。
10. **合规**：不出现政治敏感、宗教、迷信（运势/吉凶）表述。每日一签是"每天送你一句话"，不是占卜——任何"签文预示什么"的说法都禁止。

## 常见错误（上批实测踩过）

- 把 insight 压缩成 clue → 不合格（线索必须指向用户生活，不是解释原文）
- practice 写成"本周内……" → 违反规则5
- clue 问"古人如何"而不是"你如何" → 跑偏
- 三条线索互相换说法 → 违反规则4
- 漏章（输出条数 < 输入条数）→ 必须逐条对齐 id
