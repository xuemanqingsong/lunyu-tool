## 一、本次要同时完成的三个排查

对每一章，子智能体要：
1. **识别核心意群**（原文有几个核心意群，各是什么）
2. **核对情境覆盖**（每个核心意群是否有对应情境）
3. **核对讲解覆盖**（讲解是否漏掉了原文的某个核心意群/分句）

三件事基于对原文同一份理解，一次读完、一起产出。

---

## 二、核心意群的定义与识别方法

**核心意群** = 本章原文承载的、语义上独立成块的「主张/道理/行为对象」。判断方法：
- 按句末标点（？！。；）把原文切成分句，但**分句数 ≠ 核心意群数**：
  - 多个分句讲同一件事（递进、举例、问答）→ 合并为 1 个意群
  - 一个分句含并列的多个对象（如「事父母能竭其力，事君能致其身」）→ 按行为对象拆开
- 问答体（弟子问、孔子答）通常算 1 个意群（答就是核心），除非答里含多个并列主张
- 判断标准：**「如果我要把这一章讲给人听，至少要分几点讲？」**——这几点就是核心意群。

示例：
- 「学而时习之……人不知而不愠」= 3 个意群（学而习 / 朋来 / 人不知）
- 「道千乘之国，敬事而信，节用而爱人，使民以时」= 4 个意群（敬事而信 / 节用 / 爱人 / 使民以时）
- 「贤贤易色；事父母能竭其力；事君能致其身；与朋友交言而有信」= 4 个意群
- 「巧言令色，鲜矣仁」= 1 个意群
- 「吾日三省吾身：为人谋而不忠乎？与朋友交而不信乎？传不习乎？」= 3 个意群（谋忠 / 交信 / 传习）

## 三、核对规则

### 3.1 情境覆盖（scenes）
- **每个核心意群必须至少有一条情境对应**（情境描述的那个处境，能被这一意群点醒）。
- 核心意群 ≤ 3：情境 3 条就够，但要**覆盖全部意群**（不允许 3 条全落在 1-2 个意群上）。
- 核心意群 > 3：情境**应增加到与核心意群数一致**（如 4 个意群 → 4 条情境），每条对应一个意群。
- 情境之间不得重复。

### 3.2 每日行动覆盖（practices）
- **每个核心意群必须至少有一条行动对应**（这条行动是践行这一意群的具体小事）。
- 规则同情境：核心 ≤ 3 则 3 条覆盖全部；核心 > 3 则行动数 = 核心意群数。
- 行动之间不得重复。

### 3.3 讲解覆盖（insight）
- 讲解应覆盖原文的**全部核心意群**，不得漏掉任何一意群完全不提。
- 讲解可以在覆盖之外自由发挥（延伸、现实映照、边界说明），但漏意群 = 不合格。
- 判断「覆盖」：该意群在讲解中至少出现一次实质提及（同义转述也算，如「事君献身」被讲成「对上级/职责」）。

## 四、输出格式（每章一条记录，JSON）

```json
{
  "id": 12,
  "clause_count": 5,
  "core_groups": 3,
  "groups": [
    {"name": "和为贵", "scene_ok": true, "practice_ok": false, "insight_ok": true},
    {"name": "小大由之", "scene_ok": false, "practice_ok": false, "insight_ok": true},
    {"name": "不以礼节之不可行", "scene_ok": true, "practice_ok": true, "insight_ok": true}
  ],
  "needs_fix": "scenes",
  "note": "情境3条全落在「和为贵」，缺「小大由之」对应情境"
}
```

字段说明：
- `core_groups`：核心意群数（1 起）
- `groups[]`：每个意群的名称 + 三项是否覆盖
- `needs_fix`：`"none"` | `"scenes"` | `"practices"` | `"insight"` | 组合（逗号分隔，如 `"scenes,practices"`）
- `note`：一句话说明问题（无问题时写「覆盖完整」）

---

## 五、红线

1. **只诊断，不改写**：本任务只判断「哪个意群缺什么」，不产出新情境/新行动/新讲解。改写是下一步的事。
2. **忠于原文**：核心意群以本章 text 为准，不看别的章；不因别的章写过类似内容而改变本章意群划分。
3. **不苛求**：讲解覆盖是「实质提及」即可，不是逐字逐句复述；情境覆盖是「能被这意群点醒」即可，不是每个字都有对应。
4. **宁缺毋滥**：识别不出的意群不硬拆；把「讲给人听至少要分几点」作为唯一标准。
